# 云端数据备份规则说明

## 一句话总结

用户在前端**每做一次学习操作**（勾任务、传错题、收金币、传思维导图……），
同步引擎 ≤3 秒内把数据自动备份到 Vercel KV 云端；断网时先存本地，
网络恢复自动续传；多设备冲突自动保留最新时间的版本。用户侧**零操作**。

---

## 备份规则明细（已内置在代码里）

### 1. 自动备份触发规则（`src/core/sync/index.js`）

| 规则 | 说明 |
|---|---|
| 触发时机 | 监听本应用全部 localStorage 数据键的变化（计划、错题本、金币、图鉴、成就……），**任何写操作后立即触发** |
| 同步延迟 | 正常网络 ≤3 秒完成"本地 → 云端"；做了防抖合并，连续操作不会狂发请求 |
| 静默执行 | 后台自动跑，不打断用户操作，无弹窗无提示 |
| 登录才同步 | 未登录用户数据留在本机；登录后（手机号验证码 / 微信扫码）自动开始同步 |

### 2. 弱网 / 断网保护

- 断网时同步请求失败 → 数据**留在浏览器本地不丢**，同步引擎进入待重试状态。
- 网络恢复（浏览器监听到 `online` 事件）→ **自动续传**，不需要用户手动点任何东西。

### 3. 多端冲突解决

- PC 端和手机端同时改了同一份数据 → 云函数按 **`updatedAt` 最后修改时间**合并，
  永远保留较新的版本，旧版本自动丢弃，不会"互相覆盖丢数据"。

### 4. 数据隔离（不串号）

- 云端按 `userId`（登录手机号脱敏值）分桶存储，key = `sync:<userId>`。
- A 用户的数据物理上碰不到 B 用户的数据；云函数侧也有 userId 必填校验。

### 5. 存储位置与可靠性

- 存储：Vercel KV（底层 Upstash Redis），数据**持久化在磁盘**，Serverless 实例轮换不影响。
- 免费额度：30,000 条命令/月、256MB 空间——单个用户学习数据约几十 KB，
  几百个用户都够用；快到期 Vercel 会邮件提醒。
- 注意：**不配 KV 时**云函数退化为内存存储，演示可用但实例轮换会丢数据——
  所以部署指引第 3 步要求务必开通 KV 并重新部署。

### 6. 用户可自助操作（个人中心页）

- **同步状态查询**：实时显示"已同步 / 同步中 / 未登录"。
- **云端备份记录**：查看每次同步时间与数据条目数。
- **一键清空数据**：只清空本应用数据（不动其他网站数据），清空后云端记录在下一次
  同步时随之清空，隐私可控。

## 运维侧的备份建议（给站长）

1. **每月一次手动快照**：Vercel 控制台 → Storage → 你的 KV → 点进去有
   「Browse / 数据浏览」，把关键数据导出存档（5 分钟操作，防极端情况）。
2. **不要随意 Disconnect KV**：断开数据库连接不会删数据，但网站会退回内存模式，
   重新 Connect 后记得 Redeploy 一次。
3. **换域名/换账号**：先在新项目配好 `VITE_SYNC_ENDPOINT` 并 Redeploy，再切流量。
