# 上线运维常见问题手册（Vercel 免费版）

> 按「现象 → 原因 → 解决步骤」对照排查。90% 的问题都能在这里直接修好。
> 修任何配置后，记得回 Vercel 项目页 **Deployments → ⋯ → Redeploy** 重新部署一次。

---

## 一、网站打不开 / 页面报错

### 1.1 打开网站显示 404：NOT_FOUND
- **原因**：多半是第 1 步代码没传完整，或仓库是 Private 且 Vercel 没权限。
- **解决**：① GitHub 仓库里确认能看到 `vercel.json` 和 `index.html`；
  ② Vercel 项目 → Settings → Git → 确认 Connected 的是正确仓库；
  ③ 随便改一行 README 提交 push 一次，触发重新部署。

### 1.2 首页能开，但一刷新或直接访问 `/map`、`/level/foundation` 就 404
- **原因**：`vercel.json` 没上传或内容被改动（里面的 rewrites 规则负责"所有路径都回到首页"）。
- **解决**：确认仓库根目录有 `vercel.json`（和 index.html 同级）→ Redeploy。

### 1.3 页面白屏 / 控制台报 `Failed to load resource`
- **原因 ①**：浏览器装了广告拦截插件，把资源拦截了。
- **解决 ①**：换无痕窗口（Ctrl+Shift+N）打开试试，无痕里正常 = 插件问题，把网址加入白名单。
- **原因 ②**：构建产物没传上（dist 不入库是正常的，Vercel 会自己构建）。
- **解决 ②**：Vercel 项目 → Deployments → 点最新一条 → Build Logs，看有没有红色报错，
  有报错把最后 20 行抄下来对照本文档第三节。

## 二、功能异常（同步 / 数据类）

### 2.1 勾选任务后刷新，进度全没了（数据没同步上云）
- **原因 ①**：`VITE_SYNC_ENDPOINT` 环境变量没配或配错。
- **解决 ①**：Settings → Environment Variables 检查是否存在且值为
  `https://你的网址.vercel.app/api/sync`（常见错误：少了 `https://`、少了 `/api/sync`、网址打错）。
  改完后 **必须 Redeploy**（不重新部署不生效，这是新手最高频的错误）。
- **原因 ②**：没登录。同步只在登录后启动。
- **解决 ②**：先登录（手机号 + 演示验证码 888888）。

### 2.2 个人中心显示"同步失败 / 同步中"一直转圈
- **原因 ①**：第 3 步的 KV 数据库没 Connect 到项目。
- **解决 ①**：Vercel 顶部 Storage → 点你的 KV → Connected Projects，确认项目在里面；
  不在就点 Connect 补上 → Redeploy。
- **原因 ②**：浏览器控制台（F12 → Network）里 `/api/sync` 请求返回 500。
- **解决 ②**：Vercel 项目 → Deployments → 最新一条 → Functions → 点 `api/sync` → Logs，
  看报错；报 `@vercel/kv` 相关错误 = KV 没连上，回到原因 ①。

### 2.3 提示"内存存储模式，数据可能丢失"（日志里看到）
- **原因**：云函数没读到 KV 环境变量（没连库或连了没重新部署）。
- **解决**：按 2.2 原因 ① 操作后 Redeploy。生产环境必须消除这条警告。

### 2.4 手机微信里打开，样式错乱 / 很慢
- **原因 ①**：微信缓存了旧版本。
- **解决 ①**：微信右上角「⋯」→ 刷新；仍不行就右上角「在浏览器打开」。
- **原因 ②**：首次打开要下载框架文件（约 500KB gzip），弱网慢。
- **解决 ②**：正常现象，框架文件有 1 年缓存，第二次打开就是秒开。想更快可以在
  Vercel 国内访问不稳时考虑给域名套 CDN（免费平台如 Cloudflare）。

### 2.5 报错 413 / too many records
- **原因**：单用户一次性推送超过 500 条记录（一般是刷测试数据刷出来的）。
- **解决**：个人中心 → 一键清空数据 → 刷新页面重新登录，同步即恢复正常。

## 三、部署构建失败（Build 阶段红字）

Vercel 项目 → Deployments → 失败的那条 → Build Logs，对照下面搜关键字：

| 报错关键字 | 原因 | 解决 |
|---|---|---|
| `Module not found` | 依赖没装上 | 本地项目目录执行 `npm install` 后再 push；或把 `package-lock.json` 一起提交 |
| `vercel.json` 红色波浪线 / `Invalid vercel.json` | 配置文件格式被破坏 | 从仓库历史或本文档重新复制正确内容 |
| `npm ERR! 403 / E402` | npm 需要付费（一般不会） | 确认 package.json 里没有写私有源地址 |
| `Command "vite build" not found` | 依赖没装全 | 同上，重装依赖提交 lock 文件 |
| 构建超时（超过 10 分钟） | 极慢网络 | 重新点 Redeploy 重试一次即可 |

## 四、日常运维速查

| 我想…… | 操作 |
|---|---|
| 更新了网站内容 | 本地 `git add . && git commit -m "更新" && git push`，Vercel 自动重新部署，2 分钟后线上生效 |
| 查看网站访问统计 | Vercel 项目 → Analytics（免费版含基础流量数据） |
| 换自定义域名（如 shanganji.cn） | Settings → Domains → 填入域名，按提示去域名购买商处加一条 CNAME 记录指向 `cname.vercel-dns.com` |
| 数据库快满了 | Vercel → Storage → KV → Usage 查看；必要时 Upstash 控制台清理测试用户数据 |
| 完全推倒重来 | 删除 Vercel 项目 + 删 GitHub 仓库，从第 1 步重新走一遍（5 分钟） |

---

## 五、还解决不了？

1. 打开浏览器按 **F12 → Console（控制台）**，把红色报错截图。
2. 打开 Vercel → Deployments → 最新一条 → Build Logs / Function Logs，截图红字部分。
3. 对照本手册第二节、第三节的关键词搜索；仍无法解决，把两处截图发给开发者。
